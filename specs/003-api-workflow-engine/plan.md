# Implementation Plan: API Workflow Engine

**Branch**: `003-api-workflow-engine` | **Date**: 2026-08-07 | **Spec**: [spec.md](spec.md)

## Summary

Add a multi-step API workflow engine to the existing API Test Agent. Users define named workflows composed of ordered steps, each calling an API endpoint. Values extracted from one step's response (via JSONPath or header name) are injected into the next step's request. Conditions control step execution (skip or halt). Built entirely on the existing Spring Boot + file-based JSON storage + Thymeleaf stack with no new frameworks.

## Technical Context

**Language/Version**: Java 21 (LTS), Spring Boot 3.3.2

**Primary Dependencies**: Spring WebFlux (WebClient, existing), Jackson ObjectMapper (existing), `com.jayway.jsonpath:json-path` (transitive via Spring Boot, zero new dependency)

**Storage**: File-based JSON (`data/workflows/`, `data/workflow-runs/`) — same pattern as all existing stores

**Testing**: JUnit 5 + Spring Boot Test (existing `application-test.yml`)

**Target Platform**: Windows/Linux server, embedded Tomcat 10.1.26, port 8080

**Project Type**: Web application (Spring MVC + Thymeleaf + REST API)

**Performance Goals**: ≤3s per workflow step execution, ≤60s for 20-step workflow

**Constraints**: No new JS frameworks (vanilla JS only). No parallel step execution. Must not break any existing functionality.

**Scale/Scope**: Up to 200 workflows, up to 20 steps per workflow, desktop browser primary target (1280px+)
